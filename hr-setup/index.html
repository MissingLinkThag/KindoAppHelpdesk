Kindo/HR — Setup & Walkthrough Guide

Kindo/HR is an AI-powered human resources management app for Atlassian Jira. It centralizes employee records, onboarding lifecycle, workforce analytics, and HR advisory services — all stored as Jira issues in your environment.

Four AI agents work together to manage every aspect of HR operations:

Agent Roster

Agent Role Description
KNOT App Configuration Guide Setup help, health checks, discovery
HARPER Employee Records Manager Creates, updates, and queries employee profiles stored as Jira issues
ONYX Employee Lifecycle Onboarding, offboarding, transfers, with jurisdiction-specific compliance deadlines
PULSE Workforce Analytics Aggregate department metrics, capacity analysis, trend reporting

Prerequisites

  • Jira Cloud instance with Rovo enabled
  • Site admin permissions (for initial install)
  • A dedicated Jira project for HR records (created automatically on install)
Step 1

Install & Get Started

After installing Kindo/HR from the Atlassian Marketplace:

  1. Navigate to Jira Admin Settings → Manage Apps → Kindo/HR
  2. The Get Started page shows a 7-item setup checklist

Auto-completed on Install

Three items complete automatically when the app is installed:

Item Details
✅ HR project created A dedicated KHR project is created in your Jira instance
✅ HR framework applied The KinHelm HR Framework is configured
✅ Discovery scan complete Your Atlassian site is scanned for existing HR-relevant content

Requires Your Configuration

Item Details
HR team assigned Add members who will manage HR operations
Compliance requirements configured Define jurisdiction-specific compliance items
Lifecycle templates defined Configure onboarding/offboarding workflows
Peer apps connected Shows green in standalone mode

Click “Configure App” to begin setup, or talk to KNOT — your configuration agent — for guided help.

Step 2

Configure: HR Team

Navigate to Configure → HR Team tab. Add team members who will manage employee records, handle lifecycle events, and oversee HR operations.

For each member, enter:

Field Description
Atlassian Account ID Their Jira account identifier
Display Name How they appear in the app
Role e.g., HR Director, HR Coordinator

Click “Add Member” then “Save”. A green confirmation banner confirms the save was successful.

Step 3

Configure: Compliance Requirements

Navigate to Configure → Compliance Requirements tab. Define the compliance items that apply to employee lifecycle events — I-9 verification, W-4 filing, benefits enrollment, background checks.

For each requirement, enter:

Field Details
Requirement Name e.g., I-9 Verification
Jurisdiction Federal, State, or Company
Deadline Type Days from start date (business days or calendar days)
Deadline Value e.g., 3 (for I-9 federal 3-business-day requirement)
Applies To Onboarding, Offboarding, or Both

Click “Add Requirement” then “Save”. ONYX uses these requirements to calculate jurisdiction-specific compliance deadlines automatically when processing lifecycle events.

Step 4

Configure: Additional Tabs

The Configure page includes additional tabs for fine-tuning your HR environment:

Tab Purpose
Lifecycle Templates Define onboarding/offboarding checklists, transfer procedures, and probation workflows. ONYX uses these templates when executing lifecycle events.
Advisory Settings Configure KNOT's HR advisory scope — policy domains, escalation thresholds, and sensitive topic handling (ER, accommodation, separation always advisory-only).
Content Change Detection Set sensitivity for detecting when HR policies or procedures change. Changes trigger review alerts automatically.
Ecosystem View connected Kindo peer apps. The app operates in standalone mode if no other Kindo apps are installed. Ecosystem features activate automatically when peers are detected.
Tip

Accept the defaults for all tabs other than Lifecycle Templates.

Step 5

Validate Your Setup with KNOT

KNOT is your configuration guide — available anytime to check your setup, answer questions, and walk you through configuration.

How to Open KNOT

  1. Open Rovo Chat (click “Ask Rovo” in the top navigation bar)
  2. Select KNOT (Kindo) from your available agents
  3. Ask KNOT to verify your configuration. For example: "Am I set up correctly?"

What KNOT Reports

Item Details
HR team membership and roles Confirms who is assigned and their role (HR Director, Coordinator, etc.)
Compliance requirements status Lists configured requirements — I-9, W-4, benefits enrollment, and their deadline rules
Lifecycle template configuration Shows which onboarding/offboarding templates are defined and active
Discovery scan results What HR-relevant content was found across your Atlassian site — Jira projects, Confluence spaces, existing HR documentation

Example Follow-up Questions

Question Purpose
"Who is on the HR team?" Verify team membership and roles
"What compliance requirements are configured?" Review deadline rules for onboarding/offboarding
"What did the discovery scan find?" See what existing HR content was detected across your Atlassian site
Note

KNOT verifies your access level using the HR team list you configured in Step 2. HR Directors and Coordinators get full configuration visibility. All other users receive standard employee-level responses.

Step 6

Create an Employee Record with HARPER

HARPER is your employee records manager. To create an employee record:

  1. Open Rovo Chat (click “Ask Rovo” in the top navigation bar)
  2. Select HARPER (Kindo) from your available agents
  3. Tell HARPER who to create a record for. For example: "Create an employee record for Sarah Chen — Software Engineer, Engineering department, started October 12 2026, reports to Tom Rudolph, active status."

HARPER creates:

Created Item Details
A Jira Task in the KHR project (e.g., KHR-3) With the full employee details
Summary format "Employee Record: [Name]"
Labels kindo-hr, employee-record
All employee details in the description Name, title, department, start date, manager, status

HARPER can also search and update existing records:

  • "Find Sarah Chen's employee record"
  • "Update KHR-3 — change department to Product Engineering"
Step 7

Process an Onboarding with ONYX

ONYX handles employee lifecycle events with jurisdiction-specific compliance tracking:

  1. Open Rovo Chat and select ONYX (Kindo)
  2. Tell ONYX about the lifecycle event. For example: "Onboard Sarah Chen — Software Engineer, Engineering, starting October 12 2026, remote US, full-time, manager Tom Rudolph."

ONYX creates a lifecycle issue in KHR with:

Detail Example
Summary [ONBOARDING] Sarah Chen — Engineering
Compliance items with calculated deadlines I-9 due Oct 15 (federal, 3 business days), W-4 due Oct 13, Benefits enrollment due Nov 11 (30-day window)
Labels kindo-hr, lifecycle, onboarding
All hire details Name, start date, department, location, employment type, manager

ONYX calculates deadlines from the compliance requirements you configured in Step 3 — federal, state, and company requirements are applied automatically based on jurisdiction.

Step 8

Review Workforce Analytics with PULSE

PULSE provides aggregate workforce analytics — never individual employee data:

  1. Open Rovo Chat and select PULSE (Kindo)
  2. Ask for department or organization-level metrics. For example: "Show me a workforce capacity analysis for the Engineering department."

PULSE reports on:

Metric Description
Headcount and open positions Current staffing levels vs. capacity
Turnover rate and trends Historical and projected attrition
Onboarding completion status Lifecycle event progress tracking
Department capacity metrics Workload distribution and gaps
Note

When PULSE identifies data gaps or anomalies, it refers you to the appropriate agent — ONYX for lifecycle status, HARPER for record verification.

Step 9

Verify Setup Progress

Return to the Get Started page to verify your progress. After completing all configuration steps, all items should show green:

Item Notes
Compliance requirements Defined manually in Configure, or auto-populated from lifecycle templates
Peer apps Shows green in standalone mode. If other Kindo apps (Governance, Training, Compliance, Change, Legal) are installed, peer connections are detected automatically.
Architecture

Key Design Principles

  • All data stays in your Atlassian environment — Forge Storage and Jira issues. No external data storage.
  • Compliance deadlines are jurisdiction-aware — ONYX calculates federal, state, and company deadlines from the employee's location and your configured requirements.
  • Sensitive topics are always advisory-only — ER cases, accommodation requests, separation, and compensation are handled as guidance, never automated execution.
  • PULSE reports aggregate only — no individual employee data in analytics. Team minimums enforced.
  • Standalone by default, ecosystem-ready — works fully as a single app. When other Kindo apps are installed, cross-app features activate automatically.
  • Every action creates a Jira issue — full audit trail in KHR for all records, lifecycle events, and reports.
Troubleshooting

Troubleshooting

Issue Resolution
Get Started buttons don't navigate Verify the app is upgraded to the latest version (forge install --upgrade)
Configure page is blank Check browser console for errors. Ensure the app is deployed and upgraded.
Agent not responding Verify Rovo is enabled on your Jira site. Check that the agent appears in Browse Agents.
HARPER returns "Full name is required" Ensure you're running the latest version — earlier versions had a field mapping issue. Redeploy and upgrade.
ONYX not calculating compliance deadlines Verify compliance requirements are configured in Configure → Compliance Requirements.
Peer apps not detected Other Kindo apps must be installed on the same Jira site. The app works fully in standalone mode.
