Kindo HR — Security Policy

Version 1.0 · October 2026 · Annual Review Cycle

1. Overview

Kindo HR is a human resources management application built on Atlassian Forge. It provides employee lifecycle management, employee relations case handling, workforce analytics, and compliance tracking — all within the Atlassian cloud environment.

2. Platform Architecture

Platform: Atlassian Forge (serverless)

Runtime: Node.js 22.x

Storage: Forge KVS + Forge SQL

External servers: None

Credential handling: None

Network egress: None — no Forge Remote, no external fetch

4. Privacy Controls

HR data requires elevated privacy protections. Kindo HR implements the following controls beyond standard app security:

ControlImplementation
PULSE aggregate-onlyWorkforce analytics operate exclusively on aggregate data with team size minimums enforced — individual identification through small-group analytics is prevented
ER case confidentialityER cases are classified by confidentiality level; confidential cases are never exposed on dashboards or in aggregate reporting
medicalDocsInJiraHardcoded to false — the app never stores medical documentation in Jira; this cannot be overridden by configuration
Cross-app data isolationHR data is never shared via Tier 2 events; only structural metadata (event type, timestamp) crosses app boundaries
Advisory-only modeER, performance, separation, compensation, and accommodation functions are advisory only — the app provides guidance but never makes binding decisions

8. Pre-Uninstall Handler

Kindo HR includes a pre-uninstall handler that removes all app-managed data from Forge storage (KVS and SQL) when the app is uninstalled. Jira issues in the KHR project remain under the customer's control.

9. Development Security

  • Source control: private GitHub repositories with MFA enforced
  • Code review: pull request reviews required; no direct commits to protected branches
  • SAST: static analysis on every PR
  • SCA: software composition analysis for dependency vulnerabilities
  • npm audit: automated audit on build
  • OWASP Top 10 2025: development aligned with current OWASP guidance
  • Least privilege: scopes limited to operational necessity
  • Schema management: ALTER-only migrations per SOP-014 — no destructive schema operations

10. Secrets Management

  • Secrets are never hardcoded in source code
  • Environment configuration via Forge environment variables
  • Periodic rotation of operational secrets

11. Access Control

  • Per-handler permission checks — every admin function validates caller permissions before execution
  • Admin pages restricted via Atlassian's built-in admin controls
  • Confirmation gates for destructive operations

12. Vulnerability Management

  • Automated dependency scanning
  • Platform vulnerabilities patched per Atlassian's Bug Fix Policy timelines
  • Report vulnerabilities to support@kindo.ai or via the Atlassian Marketplace

13. Incident Response

  • 24 hours: Atlassian notified of confirmed security incidents
  • 72 hours: affected customers notified with impact assessment
  • 5 business days: post-incident review with root cause analysis and remediation

14. GDPR & Compliance

  • Role: Kindo acts as a data processor; the customer is the data controller
  • Data subject rights: supported via customer's Atlassian controls and upon request
  • Data location: governed by customer's Atlassian data residency configuration

15. Review

This policy is reviewed annually and updated as needed.
