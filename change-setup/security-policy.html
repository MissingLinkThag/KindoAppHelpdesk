Security Policy

Kindo/Change — Security Policy

Version 1.0 · October 2026 · Annual Review Cycle

Overview

1. Overview

Kindo/Change is an ITIL-aligned change management application built on Atlassian Forge. It provides full change request lifecycle management, impact assessment, approval workflows, post-implementation reviews, and change freeze enforcement — all within the Atlassian cloud environment.

Architecture

2. Platform Architecture

Platform: Atlassian Forge (serverless)

Runtime: Node.js 22.x

Storage: Forge KVS + Forge SQL

External servers: None

Credential handling: None

Network egress: None — no Forge Remote, no external fetch

Operational Controls

4. Operational Controls

Change management requires strict process integrity. Kindo/Change enforces the following operational controls:

Lifecycle Enforcement (MARSHAL)

MARSHAL enforces a mandatory lifecycle — steps cannot be skipped:

Draft → Submitted → Impact Review → Pending Approval → Approved → Scheduled → In Progress → Implemented → PIR → Closed

Separation of Duties (QUORUM)

QUORUM routes, tracks, and calculates approval requirements but never approves changes. Approval authority rests exclusively with designated human approvers via the CAB matrix.

Risk Advisory Boundary (BLAST)

BLAST recommends risk levels and impact assessments but never decides whether a change proceeds. Risk classification is advisory input to the approval process.

Post-Implementation Accountability (REWIND)

REWIND aggregates change outcome patterns and lessons learned but never attributes failures to individuals. All PIR analysis is focused on process improvement.

Emergency Authorization

Emergency changes require documented justification and trigger a mandatory post-implementation review. Emergency authorization logs are immutable once written.

Uninstall

8. Pre-Uninstall Handler

Kindo/Change includes a pre-uninstall handler that removes all app-managed data from Forge storage and deregisters the app from peer Kindo apps via Tier 2 notifications. Jira issues remain under the customer's control.

Development Security

9. Development Security

  • Source control: private GitHub repositories with MFA enforced
  • Code review: pull request reviews required; no direct commits to protected branches
  • SAST: static analysis on every PR
  • SCA: software composition analysis for dependency vulnerabilities
  • npm audit: automated audit on build
  • OWASP Top 10 2025: development aligned with current OWASP guidance
  • Least privilege: scopes limited to operational necessity
  • Schema management: ALTER-only migrations — no destructive schema operations
Secrets Management

10. Secrets Management

  • Secrets are never hardcoded in source code
  • Environment configuration via Forge environment variables
  • Periodic rotation of operational secrets
Access Control

11. Access Control

  • QUORUM approval matrix routing — approval requests are routed based on change type, risk level, and affected services; the matrix is customer-configurable
  • Admin pages restricted via Atlassian's built-in admin controls
  • Confirmation gates for destructive operations
  • Per-handler permission checks
Vulnerability Management

12. Vulnerability Management

  • Automated dependency scanning
  • Platform vulnerabilities patched per Atlassian's Bug Fix Policy timelines
  • Report vulnerabilities to support@kindo.ai or via the Atlassian Marketplace
Incident Response

13. Incident Response

  • 24 hours: Atlassian notified of confirmed security incidents
  • 72 hours: affected customers notified with impact assessment
  • 5 business days: post-incident review with root cause analysis and remediation
Compliance

14. GDPR & Compliance

  • Role: Kindo acts as a data processor; the customer is the data controller
  • Data subject rights: supported via customer's Atlassian controls and upon request
  • Data location: governed by customer's Atlassian data residency configuration
Review

15. Review

This policy is reviewed annually and updated as needed.
