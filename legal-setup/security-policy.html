Kindo/Legal — Security Policy

Effective: October 21, 2026 · Publisher: Kindo (KinHelm Inc.) · Quarterly Review Cycle

1. Overview

Kindo/Legal is a legal operations application built on Atlassian Forge. It provides contract lifecycle management, legal hold tracking, compliance monitoring, and legal analytics within Jira and Confluence. The app is Forge-native with no external servers, inheriting Atlassian's SOC 2 Type II and ISO 27001 certifications.

2. Platform Architecture

Platform: Atlassian Forge (serverless)

Runtime: Node.js 22.x

Storage: Forge KVS + Forge SQL

Agents: Rovo agents (5)

External connectivity: None — no Forge Remote, no external fetch, no egress

3. Agents

Agent Role Security-Relevant Behaviour
KNOT Cross-app integration router Routes structured event payloads between Kindo apps; validates source/destination identity; no raw data forwarding
ATTICUS Contract lifecycle management Manages contract workflows in Jira; tracks obligations and deadlines; read/write scoped to legal project
CLAUSE Document analysis Analyzes Confluence documents for legal clauses and terms; read-only Confluence access; no content modification without explicit action
SENTINEL Legal hold & compliance Manages legal holds and compliance monitoring; flags issues requiring legal review; advisory-only — does not enforce holds automatically
LEDGER Legal analytics & reporting Generates legal operations metrics and reports; aggregate data; tracks matter costs and timelines

4. Permission Scopes

All scopes follow the principle of least privilege:

Scope Justification
read:jira-work Read legal matters, contracts, and compliance issues from Jira
write:jira-work Create/update legal matters, contract tasks, and compliance items
read:confluence-content.all Read Confluence pages for contract document analysis and legal clause extraction
write:confluence-content.all Create/update Confluence pages for generated legal summaries and contract registers
storage:app Persist configuration, onboarding state, and operational data in Forge KVS/SQL

5. Data Collected

Category Data Storage
Configuration Admin settings, workflow preferences, notification thresholds KVS
Onboarding State Setup wizard progress, initial configuration choices KVS
Operational Data Matter metadata, contract lifecycle state, compliance tracking, analytics Forge SQL

Data NOT Collected

  • No personal data beyond Atlassian accountId
  • No credentials — the app never stores, processes, or transmits user credentials
  • No external data — no data is imported from outside the Atlassian environment
  • No external telemetry — no usage data is transmitted outside the Forge sandbox

6. Data Residency & Retention

  • Data residency: all data resides within the Atlassian Forge environment; residency is governed by the customer's Atlassian configuration
  • Pre-uninstall handler: removes all app-managed data from Forge storage on uninstall
  • Customer content: Jira issues and Confluence pages created by the app remain under the customer's control after uninstall
  • Key management: Kindo does not manage encryption keys — key management is handled by Atlassian

7. Encryption

Layer Method Managed By
In transit TLS 1.2+ Atlassian
At rest — KVS Encrypted Atlassian
At rest — SQL Encrypted Atlassian
At rest — Confluence/Jira Encrypted Atlassian

8. Vulnerability Management

  • SAST: static analysis in CI/CD pipeline on every pull request
  • SCA: software composition analysis for dependency vulnerabilities
  • Input validation: type guards and parameterized SQL for all inputs
  • Dependency updates: continuous monitoring and automated update tooling

Vulnerability Disclosure Program

  • Report to: security@kindo.ai
  • Acknowledgment: within 48 hours
  • Triage: completed within 5 business days

9. Incident Response

Kindo maintains a documented incident response plan covering identification, containment, eradication, recovery, notification, and post-incident review. Timelines are aligned with contractual and regulatory requirements.

10. Access Control

  • Admin install: app installation restricted to Jira/Confluence administrators
  • asApp() scoped: all API calls execute under the app's identity with defined scopes
  • getTeamList validation: team-based access controls enforce visibility boundaries
  • GitHub branch protection: protected branches with required PR reviews; individual authentication only (no shared credentials)
